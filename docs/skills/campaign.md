# Campaign

Loose idea → cleared decision graph → gauntlet-verified product, autonomously. This composes four things that work badly apart and well together: **research** (pre-map the landscape), **wayfinder** (the graph: decisions as tickets, blocking edges as the frontier), **the goal loop** (a stop condition that keeps the orchestrator driving), and **the blind gauntlet** (builder vs fresh-context cross-lineage critics, looped until the artifact beats a real-world reference).

```
GOAL → [RESEARCH] → CHART (graph) → DRIVE (goal loop) ⇄ BUILD (parallel lanes) ⇄ GAUNTLET (blind critics) → DESTINATION
```

The orchestrator (fable-5; opus fallback on rate-limit) never implements and never reviews — it charts, routes, adjudicates, and merges. Every other role is a subagent with exactly one job.

## Phase 0: GOAL

Two questions are genuinely the user's; ask them once, together, and nothing else:
1. **Destination** — what does "done" look like (a spec? a decision? a shipped phase?). Recommend the option matching the project's own sequencing doc if one exists.
2. **Tracker** — where the map lives. Prefer a tracker with **native blocking** (GitHub issues + sub-issues + dependencies API; Plane relations). Local markdown is the no-tracker fallback.

If the user sets a goal/stop condition ("reach X, fully featured"), record it in the map's Notes as an **execution override**: the map carries execution, HITL pacing is overridden, and grilling-type decisions resolve autonomously **on recorded authority** — the project's spec docs, research briefs, and prior decisions — never on invented preference. Every autonomous resolution says so and is reopenable.

## Phase 1: RESEARCH (optional but cheap to skip wrongly)

If the effort has prior art (an existing corpus, a competitor, a design lineage), run `/research` first. Its BRIEF.md becomes a **settled input** listed in the map's Notes — tickets reference it instead of re-litigating it. Skip only when the landscape is genuinely bare.

## Phase 2: CHART

One session. Repo + tracker infrastructure first (git init / labels: `wayfinder:map`, `wayfinder:research|prototype|grilling|task`), then:

1. **Map issue** (`wayfinder:map`): Destination · Notes (spec docs, settled inputs, methodology, model routing, skill adaptations) · Decisions so far (empty index) · Not yet specified (the fog) · Out of scope.
2. **Decision tickets** as child issues — a ticket is a question you can state precisely NOW (blocked is fine; vague goes to fog). Body = `## Question` plus context links. Types: research (AFK), prototype, grilling, task.
3. **Wire blocking second** (issues need ids): sub-issues under the map + native blocked-by edges. The frontier = open ∧ unblocked ∧ unclaimed, visible in the tracker's own UI.
4. **Fire research subagents immediately** — they are the one type charting resolves. Parallel, findings on throwaway `research/<name>` branches, resolution comment + close, orchestrator indexes the gist into Decisions-so-far as each lands.

## Phase 3: DRIVE (the goal loop)

Repeat until the destination holds: take the frontier, resolve it, graduate the fog, dispatch builds. Rules proven in the field:

- **Decision tickets**: resolve with a `**Resolution**` comment stating the answer, the authority it rests on, and "reopen if wrong"; close; append one gist line to the map's Decisions-so-far. Detail lives in exactly one place — the ticket; the map only indexes.
- **Fog graduation**: when a resolution makes a build specifiable, create the build ticket **enriched at birth** — never sparse. Required sections: `## Question` (one line), `## Context` (links to governing resolutions), `## Touches` (paths), `## Acceptance test` (concrete, runnable), `## Verification gate` (the commands that must be green), `## Scope boundary` (what NOT to build; name the ticket that owns it), `## Gauntlet` (the real-world reference + which judges). A build ticket an agent can't pick up cold is a defect.
- **Tickets decay between writing and dispatch**: the orchestrator writes them from session memory, and lanes advance underneath. Every builder prompt says *verify the ticket's factual claims against the tree and report each contradiction rather than inheriting it*. Measured: one short ticket written from memory carried four wrong facts (branch count, heading count, a spec's own enumeration, two lanes a round stale) — all four caught by the builder in its first pass.
- **Tell agents waiting on long jobs to block, not report.** An agent that checks a running job, reports progress and stops turns the wait into a poll loop through the orchestrator — measured at three near-identical updates from one round, none carrying information. Say "block on the process and send one message when you have the answer", and enumerate in the dispatch exactly what that message must contain.
- **Give shared doctrine an append-only slot, and simulate the merge train early.** Measured: seven parallel lanes produced **zero source conflicts** and five conflicts on one prose file, because nearly every round's brief required a doctrine correction — a merge conflict specified in advance. Either give each lane a dated append-only section, or schedule doctrine edits as one pass after the train. And **simulate the sequential train in a throwaway branch long before you need it**: it costs one command, and a pairwise conflict matrix (which showed 9 of 10 pairs conflicting) is technically correct and practically misleading, because it never models the sequence anyone will actually perform.
- **Set `isolation: worktree` on the dispatch.** Telling an agent in prose to "work in your worktree" does not create one — measured: of two fix rounds dispatched with the instruction but without the parameter, one complied and the other ran `git checkout -b` in the orchestrator's own primary working directory, moving the session's checkout onto a build branch mid-run. Related habit that contained it: **every scripted edit asserts the text it expects before writing**, so the wrong-branch edit failed loudly instead of appending a file's history onto a branch that never carried it.
- **Parallel lanes**: anything whose blocking edges are clear AND whose files aren't being reshaped by an in-flight fix round can run concurrently — worktree isolation per builder, distinct branches, orchestrator owns merge order. Do not build atop files a fix round is rewriting; that's the one dependency the graph doesn't show.
- **A disagreement between lanes is a merge-tree property until proven otherwise**: when two parallel lanes measure the same property and get different answers, do not assume one measured badly. Ask which half of the mechanism each branch holds — the shipped behaviour is frequently visible from neither vantage point, and a branch-local measurement of a cross-branch property is not evidence about what ships. Keep the ticket that owns the number open until it is re-measured on the merged tree.
- **Never fabricate progress**: index only what a notification confirmed; a pending agent's result does not exist yet.
- **Reconcile the board against the *tracker* on a schedule, and weight the sweep by consequence.** Three lanes stalled in one campaign, each found by accident: two with a pushed branch and no gauntlet dispatched, one with a receipt never written. The mechanism is always the same — **attention follows notifications, and a lane that stopped producing them is indistinguishable from a finished one.** The lane most likely to go unnoticed is the one nobody is arguing about, which in one case was the auth boundary. Diff every lane's latest pushed branch against its latest receipt, don't trust the felt sense of having kept up.
- **Reconcile the board against the actually-running agents, periodically.** A dispatched agent is not a running agent. Measured twice in one campaign: two branches reported as live for fourteen hours were never gauntleted, and two critics vanished without reporting, leaving a pushed and receipted branch with no review at all. The drift is always in the direction that looks like progress. Also re-derive what a critic is pointed at from the tracker at dispatch time — one pair was aimed at a branch that did not yet exist, so even a verdict would have described superseded code.

### Concurrency is a hard gate, not a courtesy line in a brief

**Check load before every dispatch and cap concurrent heavy agents at `cores/2`.** Not advice to the builder — a check the orchestrator performs and acts on.

Measured cost of not doing this: four heavy agents on four cores drove load to 21.94, then 12.22, then 9.61 across one campaign. One round lost **ninety minutes of state walk** to a starved page load at transition 2,800 of 5,303. Another produced a check that fired once and could not be reproduced in fourteen runs — a ticket filed against the machine, not the code. Browser suites emit `Protocol error (Runtime.evaluate)` under contention, which reads as a product defect and costs a re-run to disprove.

The failure mode is subtle: writing *"nothing heavy concurrently"* into a brief moves the obligation to an agent that cannot see the other three. **Only the orchestrator knows what else is running, so only the orchestrator can enforce it.** Concretely: read load average before dispatching; if it exceeds cores, wait rather than queue; treat a starved run as an orchestration defect and say so in the receipt rather than letting the round attribute it to the artifact.

**And measure what a round costs.** Subagent token counts arrive with every completion — tally them per lane. A campaign that cannot say what a lane cost cannot notice a lane costing more than the destination is worth, which is the drift above wearing a different face.

### The destination gate (added after a campaign drifted for a day)

**Before dispatching any round, name the destination ticket it unblocks.** "None directly" is a legal answer and must be stated. Count consecutive dispatches that unblock nothing — that number drifting upward *is* the drift signal, and it is the only one the loop produces.

The exit rule below stops a *lane* escalating. It cannot see that the frontier moved, because it asks one question about one artifact. Measured: twelve rounds across five lanes, every one finding a real defect, while the destination's own two build tickets sat at zero comments and zero branches. **The gauntlet loop is a quality mechanism, not a scheduler — the map is the scheduler.** Keep an explicit critical path on the map and re-read it at every dispatch.

**Merge continuously.** Lanes that diverge for days compose in ways nothing local can see: two branches, each internally consistent and each passing a terminal blind review, produced a dead product path with **zero merge conflicts** because their rules lived in different files and different languages. It surfaced as one red integration test on a tree where typecheck, lint and 2909 unit tests were green. Rebase lanes onto a shared integration branch daily and run the **integration** suite on the merged tree — a green typecheck proves nothing about a producer and its checker disagreeing.

## Phase 4: BUILD

**Resource discipline — measured the hard way.** Nine hours of unbounded dispatch on a 4-core box reached load average 21.9 sustained (5.5x oversubscribed), 25 of 31 GB used, 48 Chrome and 14 vitest processes, 9 database containers — and one dev server holding **16.5 GB and 91% of a core for 2h33m**, belonging to a critic that had finished hours earlier. Three rules:
- **Cap concurrent heavy agents by cores, not by lanes** (~2-3 on 4 cores). A queued lane costs nothing; an oversubscribed box slows every lane at once and hides which one is stuck.
- **Every completion notification is a reap point**, not only a cue to dispatch the next round — kill processes rooted in the agent's temp dir, remove containers it created, delete its clone.
- **Put teardown in the dispatch**: "tear down anything you start — dev servers, containers, `/tmp` clones — and say in your report what you tore down." One critic did this unprompted at zero cost; the rest left infrastructure behind and none of them were wrong to, because nobody had asked.

Model routing (shape, not smartness ladder — per ~/.claude/CLAUDE.md):
- **Iterative in-repo work** (must run suites, react to failures): opus-5 native subagent, `isolation: worktree`.
- **Self-contained specs** (mechanical, isolated diffs): codex `gpt-5.6-terra`, high effort, via a thin sonnet relay wrapper running `codex exec`.
- **AFK research**: sonnet scouts (web + write brief + branch + resolve ticket).
- **Taste-critical artifacts** (UI, prototypes): opus-5 minimum.

Builder contract (put it in every prompt): work from the correct base branch (often another unmerged build branch, not main — say which); verify with the ticket's gate before pushing; push the branch; post a comment with what was built + verification output; **leave the issue OPEN** — only the orchestrator closes, and only after the gauntlet. Commits end with the standing co-author line.

## Phase 5: GAUNTLET

**Before the first round, write down what the artifact defends against and who the adversary is** — and re-read it whenever a lane passes round five. Measured, at a cost of roughly five rounds: a CI gate was hardened for ten rounds against defects that all required editing the gate's own source in the same commit, while the same reviews confirmed it caught real regressions on a live stack. A gate defending against *accidental regression* terminates — plant a real defect, require the red. A gate defending against *its own maintainer* is unbounded, because the maintainer can always change the gate; the control there is review of changes to the gate, or a check the author cannot edit in the same commit, not another round. **Each round in an unbounded game produces a genuine finding and reduces nothing, which feels exactly like progress.**

**The one question that generalises every defect this process has caught: _if I flip the input, does the output move?_** Structure proves where a value came from; only mutation proves it was *used*. A gate whose assertion ran but whose result nothing consumed, a flag required present whose value is never read, a receipt handed four views that uses none, a ledger crediting a catcher it never ran unmutated, an audit reporting "0 failed" over a selector matching nothing — all one shape. Put it in every critic prompt and every builder's verification gate.

Every build ticket passes a blind gauntlet before it closes. The mechanics that make it work:

- **Phrase critic instructions as content requirements, never as directives about the message envelope.** A critic prompt ending `VERDICT (final message, raw): …` plus rules about output format tripped an automated monitor as an apparent attempt to redirect *its* evaluation role — a false positive whose cause was the prompt's shape, not the agent's behaviour. Ask for "a verdict line stating PASS or FAIL, most severe first" and for the read-only constraints as scope ("do not push, comment, or edit"), rather than instructing the agent how to format the final message. When such a flag does fire, **verify rather than argue**: check whether anything was written (refs pushed, comments created), then independently confirm one or two of the review's sharpest claims against source. Both checks are cheap and they settle honesty far better than reasoning about the flag does.
- **A builder may not take evidence from the review that judges it.** Even a byte-identical tree only makes another run's numbers *applicable*, never *independent* — a verdict and the claim it assesses citing one measurement is no longer a gauntlet. When the two would share a source, the builder keeps the smaller honest number: a true "48 unmeasured" beats a larger figure with tangled provenance, and the next round then knows what it inherits.
- **Any run whose result is evidence needs exclusive ownership of every piece of mutable state it touches** — a gate, a suite, a mutation pass, a benchmark. Measured twice in one hour on one database: concurrent mutation runs make another run's state indistinguishable from a mutation being caught, *and* an integration gate went green against a schema a second session was actively mutating. **A shared database makes a green unattributable as well as a red, and the green is the dangerous one because nobody investigates it.** One database per run, on its own port, with nothing else connected.
- **Blind means blind**: critics get fresh context, never the builder's notes/comments/commit messages, never each other's findings, and never write to the tracker. They are read-only and report to the orchestrator only. (If critics posted mid-review, the second critic would correlate with the first and an unadjudicated claim would stand as record.)
- **Cross-lineage by risk**: default = one foreign-lineage critic (codex) or one fresh Claude. Anything touching **trust, security, concurrency, auth, or a git-write path** runs BOTH foreign lineages (codex gpt-5.6-terra high + grok-4.5) — measured to catch disjoint defect sets. Rendered/visual artifacts add a Claude critic that actually drives the page (agent-browser, screenshots, both themes).
- **Relay wrappers**: sonnet, effort low, one **foreground** Bash call, stdin `</dev/null` **placed before the output redirect**, real timeout, relay verbatim. The orchestrator writes the CLI invocation into the prompt, so an omitted redirect is the orchestrator's bug reproduced faithfully — put it in every dispatch. Symptom to recognize instantly: the run sits for the full timeout and its output file contains only `Reading additional input from stdin...` (~39 bytes). That is a hang, not a result; kill, re-run with the redirect, and never report it as clean. State explicitly that the wrapper must not background the CLI or return before it completes — a wrapper that backgrounds a long run and reports "it's still running" burns the run and yields no verdict. A missing verdict is never a pass; re-run it. Capture output to a file — piping through `tail -c N` truncates the verdict header off long reviews. Confirm codex's `model:` header; models misreport their id if asked.
- **A critic's "I could not execute" invalidates the round's verification claims — go run them.** Measured, and it cost a full round: a builder reported "full gate green", the critic honestly reported it had no `node_modules` and could not run anything, the orchestrator wrote that down as a caveat and filed the gate claim as fact — and the branch did not build (two TS2345 errors, exit 2). **Never repeat a builder's gate claim in a receipt without either a critic that executed it or running it yourself.**
- **Freeze the tree for the duration of a review.** A round editing files while a reviewer reads them produces "source and `dist` diverge" and a verdictless run. Two distinct causes produce that same symptom — a network-isolated sandbox failing `pnpm install`, and a moving tree — so diagnose per instance rather than reusing last time's confident answer.
- **First task of any round inheriting a file with rationale comments: audit them.** Take every "this cannot happen because…" and ask what the code *does* with an input inside it, as a table. Measured: that sweep found a defect four blind review passes had missed — a near-duplicate check that silently *discarded* a reading contradicting an accepted object, leaving what it contradicted standing.
- **Run the self-adversarial pass until a pass changes nothing.** Measured: four passes, each breaking the previous one's fixes, including three comments the round wrote to justify its own code; two bypasses were *created* by fixes for earlier bypasses. A round's own justifying comments are prime targets — written with the most confidence and the least scrutiny.
- **Prepare the critic's tree before handing it over.** Install dependencies and build first. A read-only, network-isolated sandbox must constrain *writing*, not *running the suite* — a critic that cannot execute the tests either stalls out with no verdict (measured: three verdictless runs traced to `pnpm install` hitting `EAI_AGAIN`, then hunting `node_modules` in unrelated checkouts) or downgrades itself to static analysis. Ask every critic to mark its evidence tier — executed vs. read — and believe the executed claims first. When a run ends with no verdict, recover its session log before discarding it; the diagnosis above came entirely from a transcript the CLI's stdout never showed.
- **Grep the prose, not just the code**: a comment naming a failure mode marks the moment its author was thinking about that failure — which makes the adjacent code the highest-yield place to look, not the safest. Measured three times in one day across three lanes: the line causing the defect sat directly under a docblock describing the defect's class. When a fix round closes a defect, check every sibling field, call site and branch that the surrounding comment governs — deriving one field of a record does not derive the record.
- **Adjudicate before acting**: a finding is a hypothesis. Verify the top findings against source yourself. Critics can't see the map, so they will re-derive scheduled work as "missing" — route those findings to their owning tickets (append to the ticket body) instead of treating them as defects or dropping them. Independent convergence of both lineages on the same gap is the strongest signal in the whole system: believe it. **And divergence is the second strongest — treat it as a located question, never resolve it by recency.** When it resolves, the answer is often that **parallel lanes are different systems**: measured, two lanes had no merge-base in either direction and were two different servers with the same filenames, one with room content and no revocation sweep, the other with a sweep and no room content — so neither could answer the question and it became a merge-train ticket. **Before relaying a claim from one lane to another, check whether the lanes share the code the claim is about.** Two further rules fell out: a guarantee measured where the thing it guards does not exist is not a measurement; and a number produced under a test override (an e2e interval of 1 s against a 15 s default) is a property of the override. Measured: two executed reviews gave opposite answers on whether a revoked member keeps receiving room content, and the orchestrator had already published a correction citing one as fact. Publish the contradiction *as* a contradiction, say the bound is unknown, and dispatch a resolution that reproduces both procedures against one server and reports the separating precondition — two good reviews disagreeing have located something neither would have found alone.
- **A stronger mutation does not subsume a weaker one.** Deleting a check tests that it exists; weakening it tests what it means. Measured: a ledger's mutant deleted all three `.innerJoin` lines, while dropping only the *correlation* from one join passed 820 unit tests and 45 e2e and was a real cross-workspace read. For every join, predicate or comparison, mutate the condition rather than its presence.
- **One gauntlet receipt per round**, posted on the ticket: each critic's verdict, what survived adjudication, the routing table (fix round vs owning tickets vs noted-not-blocking), and what round 2 requires. The receipt is the ticket's audit trail — same "everything leaves a receipt" rule wayfinder preaches.
- **The self-adversarial pass's first target is the diff of the fix itself.** Measured, twice in one campaign: a round fixed a critical self-exempting checker and then found **seven further defects, every one being the class it had just named, committed inside the commit that named it** — a scanner checking a basename where it meant a location, a constant written in the change arguing against constants, and an invocation graph proving *presence* one file after the author wrote that presence is not use. While you write the fix you are thinking about the old defect, which is exactly the state in which you commit it in the new code. Give the pass the named class as a checklist and the fix's own diff as the target, before the surrounding artifact.
- **Centralising N copies of a check converts N independent failures into one total failure, and the tests written for the N copies do not transfer.** The sharpest defect of an entire campaign: a round correctly replaced fifteen copies of a guard with one shared predicate, built a real outside witness for every enforcement check — and the witness never called the new predicate, because it tested the guard's *shape in the callers*. One statement in that one file silenced 358 assertions with the witness passing 49/49 and lint clean, where the defect it replaced had cost two edits in two files for 316. **When a refactor introduces a shared implementation, that implementation needs its own registered, outside-invoked, failing-fixture test the same day.** Ask of every de-duplication: what did I just make single-point, and what watches it?
- **Give a critic the resources to run the thing.** Measured: four rounds argued about a deploy gate from fixtures; one critic with a writable workspace stood up the real compose stack, ran all 15 stages green, deleted one `COPY` line from the Dockerfile, and got the exact named assertion to fail with a 404 — settling in one pass what fixtures had left open for four rounds.
- **When a defect's root cause is a structural change, key the rule on the structure — do not sweep the instances.** A sweep is dated the moment it lands. Measured as the right form: after a de-duplication created a single point of disarmament, the fix was not "register that module" but **"fail the build when any module here has ≥3 importers and no registry row"** — catching the *next* thing that becomes shared on the day it becomes shared. Registry went 5 → 14 rows and an independent audit of blanket stubs returned 14/14 sensitive.
- **Diagnose a flake to its cause; never retry it and never raise the timeout.** A retried flake is an unmeasured failure and a raised timeout is an unstated claim that nothing got slower. Measured: a 1-in-5 suite failure was a 5s timeout wearing an assertion's clothes, fixed at the cause (a parse memo, 2.2s → 0.4s warm) and then demonstrated over eight consecutive clean runs.
- **A positive control must assert *which* failure occurred, not that one occurred.** The sharpest defect of an entire campaign: a control planted a real defect and treated exit 0 as its failure — correct design — but matched on bare script names, which any stack trace supplies for free. Its assertions were crashing on a missing file written six steps later, so the control proved them red for the wrong reason, which is the exact case its own rule existed to reject. **An expectation matching an artifact's identity is satisfied by any failure that mentions it; only one matching its behaviour proves anything.** **When a denylist goes stale, climb rather than extend it: generate → observe → allowlist.** Measured across two rounds — a listed corpus went stale the moment a fix changed a failure's shape; the next round *generated* the corpus by running the shipped code over each world it distinguishes (catching two controls nobody had listed), then **stopped matching strings** by requiring the same entry point to produce *different output* against a live target and a decoy (615 identical bytes before, 1955 vs 1302 after), then allowlisted what counts as an assertion at all (it must read a value), so the next tautology spelling needs no enumerating. Each rung removes a class of staleness rather than an instance. **Enforce it with a corpus of wrong reds** — a stack trace naming the script, an `ENOENT` naming it, a syntax error, a command-not-found, a bare connection refusal, a signal — and refuse any expectation that one of them satisfies, before spawning anything. That turns the rule into a mechanism the next round cannot forget, and it generalises to any matcher or error-classifier.
- **Prove the check fires, not that it exists.** The general resolution of that class: every registry row carries a `violate` fixture the check must go red on, so a check gutted to `return []` fails regardless of how good its call graph looks. An invoker that cannot execute is not an invoker; a fixture that no longer violates proves nothing.
- **Self-adversarial pass on verification work**: when a round's deliverable *is* a verification mechanism (a policy engine, an audit, a ledger, an invariant checker), the builder runs a blind foreign-lineage review of their own output before reporting, and lists what it broke. Measured in the field: this caught fourteen real bypasses including one a rule had claimed to ban for two rounds — more than the subsequent gauntlet would have. The builder who just wrote a guard is the best-placed person to attack it and the worst-placed to trust it.
- **Standing design rule critics must check — allowlist the compliant form, never denylist the violations.** A denylist refuses only what someone thought of, and its gaps fail open and silently. This arrived independently three times in one day on one project (a CI launcher policy that missed `setsid`; a UI narrating a change via a denylist of misleading phrasings; a tokenizer whose character class deleted non-Latin script and negation particles). Every guard, parser, normalizer, narrow `catch`, and "safe list" is in scope. Best form: derive the assertion from the same computation that authorizes it, so no list exists. Corollary for reviews: **independent convergence on one structural principle across unrelated subsystems promotes it from lesson to rule** — record it, don't rediscover it a fourth time.
- **Audit the invocation graph, not just the rules.** For every check, ask who runs it and whether the thing being checked can disarm its runner. Measured, and the sharpest defect of the campaign: a rule requiring a canonical guard string was a substring test over the whole file; the self-test that was its *only* invoker held that string as a fixture, so it satisfied the rule no matter what its real guard said — and two `&&` insertions then deleted 316 assertions with lint, policy and both CI steps green. Two standing rules follow. **A test suite necessarily contains examples of what it forbids, so any rule enforced by scanning file text will always exempt its own tests** — enforce at statement position, or build fixtures from concatenated halves. And **a check whose only invocation is inside the file it checks is not a check.**
- **Distinguish "refused by the rule" from "did not happen to break".** A control that holds only because of some unrelated tool's incidental behaviour is not a control, and it stops holding silently the day that tool changes. Ask critics for this distinction explicitly, and treat a reported-but-non-reproducing gap as a finding rather than noise.
- **A compile-time assert is code; require a fixture proving it fails.** The layer that looks most authoritative is the easiest place to ship an inert check. Measured: a design's whole guarantee rested on `X extends 'event'|'catchup' ? never : true`, which resolves to `true` regardless — a union only extends a target when *every* member does — beside a comment claiming `tsc` would refuse the build. Every type-level assert needs a companion `@ts-expect-error` fixture on the violating shape, or it is a comment with syntax.
- **Make an incomplete measurement say so in the artifact, not in the receipt.** A caveat in a report nobody re-reads does not survive; a stale number in a committed results file becomes a claim. Measured as the right form: a ledger that grew 58 → 71 with only 23 entries re-measured shipped a banner reading "the other 48 are unmeasured on this tree, not passing on it" — in the file a reader would otherwise take the number from.
- **An adjudication that names a discharge must appear in the very next brief, or it is a note.** Measured, and it cost a live defect: an orchestrator ruled that a receipt certifies provenance and not speech-act, named two ways to close the gap, and did not require either in the following round — where a foreign-lineage sweep then found the gap being exploited as the round's worst finding. **A written-down gap that is not converted into a required change is indistinguishable from an undiscovered one, except that the record shows you knew.**
- **Before writing a check, name who controls each value it reads.** This is the sharpest form of the scope rule and it subsumes several others. Measured: a gate refusing acceptance when a scan "read nothing it did not already control" tested a window derived from the proposal's own citation list — so citing one extra *earlier* message flipped refusal into acceptance, at both enforcement points, with the same words and the same author. **A rule over a parameter the constrained party supplies measures that party's cooperation.** And the fatal version is not adversarial: an ordinary extraction hit it on the first try. Require every check to state, in source, who supplies each input and why the check is still meaningful given that.
- **A test that carries a claim needs an explicit timeout and a measured margin.** Measured: the two brute-force property tests underwriting a round's headline sat on vitest's 5000 ms default while one of them took 5277 ms on an idle machine — six consecutive runs gave 1, 1, 0, 1, 0, 0. A round whose posture is "we measured it rather than argued it" had the measurements as the flaky part, and a slower box fails always. When a flake appears, bound its blast radius before dismissing it: check whether the flaky test is named as a catcher anywhere, and say what the flake does and does not invalidate.
- **Never stage broadly while a harness mutates in place.** Measured: `git add -A` during a mutation run committed a live mutant, and `git status` reported it **backwards** — the correction showing as an uncommitted edit and the defect as nothing, because HEAD held the mutant and the tree held the truth. Stage explicit paths, or gate staging on the harness being provably stopped. Fourth distinct injury from one property (a runner surviving `TaskStop` twice, a reviewer reading a mutated file as source, a committed mutant).
- **Review from `git archive HEAD` or a copy whenever any harness in the repo mutates in place.** A mutation runner rewriting `src/` even in `--check` mode means reading the worktree returns a mutant, not the code — and the person most likely to be misled is the next reviewer, so warn them in the file.
- **Write every rule's scope down as a separate sentence, and attack that sentence.** Two lanes failed the same way on the same day, both after doing the hard part correctly. One built a genuine allowlist over a command's exit *value* and scoped it to the guard body — leaving one line at module top level that silenced 381 assertions. The other re-derived its enumeration from the expression grammar and never re-derived which files it parsed — leaving a `.js` route that served the whole membership table unauthenticated. **The scope is invisible while you reason about what happens inside it**, so it has to be stated and attacked as its own claim. Third instance in one review: a rule keyed on the wrong unit (per-module rather than per-export) is the same defect wearing a different hat.
- **When a rule uses a count, check what sits at count−1 and say why it is safe there.** Measured: a registry required a row for any module with ≥3 importers, and the module at **2** was the extraction that had fixed the previous round's defect — sole enforcer, sole exception, one importer under the line. The item most likely to be just under a threshold is the one recently extracted to fix the last thing.
- **Tie a checker's file list to what actually executes, and assert the difference is empty.** Four subsystems in one campaign shipped a correct analysis over an incomplete input set: an import analyser skipping `.js` while `allowJs` was on and the framework served `route.js` (fixing it went 79 → 127 files); four instruments hard-coding one viewport for thirteen rounds; a printed-string sweep reading `*.tsx` under two directories; a tokenizer whose character class deleted non-Latin script. **A guard's file list is a claim about the world and it is the claim nobody tests**, because every test is written against the shapes, and the shapes are fine. Derive it from the bundler's module graph, the framework's route conventions, or the compiler's `include`.
- **A walk that recurses on recognised shapes and returns on the rest is an allowlist that fails open.** Measured twice on one boundary: a `Set` and then a React portal (whose `$$typeof` makes `isValidElement` false) both walked past a slot validator, which then rendered the forged provenance token the validator existed to prevent. Refuse the unrecognised and enumerate what that refuses.
- **A guard with a universal claim has two denominators: the shapes it understands, and the inputs it looks at.** Hardening one while never examining the other is how a lane loops. Measured over ten rounds: six each closed "the sixth escape" by adding the shape the last critic found; the seventh turned out to be that the analyzer never parsed `.js` files while `allowJs` was on and the framework served `route.js` as a route, skipped any directory named `test` anywhere including the framework's own routes, and silently waved through anything resolving outside its roots. **The unifying fix is one rule: fail closed on anything the analysis did not parse** — "we could not tell" must never render as "it was fine". Ask of every enumeration: what does it enumerate *from*, and what can exist that the source does not list?
- **Validate a new detector against the version it was written to catch, with an independently derived expected count.** "It flags the reported defect" is the weakest possible evidence — that is the one case you had in hand. Measured: a new sweep run against the previous revision reported **53 findings where 68 were due**, and the fifteen it missed contained all four sinks it existed for. Check false positives against a known-good population too; an earlier revision of the same instrument over-refused and reproduced, in its own checker, the defect it was written to end.
- **A mutation must be the shape the rule forbids, not merely a shape the compiler rejects.** Measured: a guard claiming "no such field can exist" was pinned by adding a *required* property and requiring `tsc` to fail — which proves only that fixtures break. The field that falsified the claim was optional, and a compiler cannot refuse one. When a rule is about what *can* exist, mutate toward the permissive case.
- **Every audit asserts its own denominator.** "N inspected, 0 failed" is evidence only when N is checked against an independently derived expectation — otherwise "0 failed" is indistinguishable from "0 looked at". Measured: a sweep selector matched zero elements (every class was a CSS-module hash) and reported clean; a contrast check compared a border against only the friendlier of its two adjacent colours, letting one token survive four passes; a graphic was composited against its own background and measured 1.00:1 as a pass. **Audit the instrument on the same schedule as the artifact** — twice in one day the instrument was the defect, and a wrong instrument invents clean results as readily as it invents findings.
- **First option in any fix round: can the field, argument, or option simply not exist?** A guard over a carried field is always one field behind the last round. Five independent arrivals across five subsystems in one campaign — delete the address and look it up at the render boundary; derive the narration from the comparison that authorizes it; allowlist the compliant form; allowlist the launcher; delete the argument rather than validate it. Ask it before designing a check.
- **Ask critics to pivot, explicitly.** A reviewer that reports "I could not break X" and moves to the side channels is doing the job. Measured on one artifact: two foreign lineages produced nine defects with **zero overlap** — one broke the display path five ways, the other could not, said so, and found four defects nobody was looking at. Put "if you cannot break the headline, say so and go elsewhere" in every critic prompt.
- **Account for every span, not just the mutation**: a point-read mutation proves a read is *used*; it does not prove the whole sentence came from reads. A generated string built from one real field plus a literal suffix passes the mutation test cleanly while the literal is a free-floating lie. Ask what produced each fragment; any formatter with a `pre`/`post`/`prefix`/`suffix` parameter beside a real field name is where an unfalsifiable claim hides.
- **Mutation claims ship with a re-runnable ledger**: "N mutations, N caught" is not evidence unless a reviewer can execute the mutant list and see the results. Commit the script and its output, or drop the claim. **Require the ledger's strictest mode — *caught, but not by the named test*.** A plain "did the suite go red" check is not enough: measured, a round scored 114/114 under that reading and was wrong three times. **Any round landing more than one refusal must re-run that mode at the end**, because two fixes can de-discriminate each other's tests — a fixture written for one rule that also trips a rule added later makes its assertion true for a new reason, with nothing in the diff to show it. Pick fixtures minimal against the rule they pin, not realistic. **And the ledger must run each catcher unmutated first, refusing the entry if it is already red** — measured: a suite exiting 1 on a clean clone (a render throw reaching the global handler after the test's own `catch`) caused every mutation naming that file to be credited automatically, inflating a reported "101/101". Green-on-mutation is meaningless without red-on-baseline, and a broken test is otherwise indistinguishable from a perfect one. Check the suite's exit code on a fresh clone, not in the worktree where it was built.
- **When a round names a defect class, the deliverable is the enumeration, not the diff.** Ask for the mechanical list of every call site of the pattern, in the receipt. Measured diagnosis of an otherwise excellent round: *"every lesson it learned was applied to that row and to no more than one neighbour of each kind"* — the correct fix, applied once, four times over.
- **Name the mutation**: every test a builder adds or changes must state the source mutation it now catches. A fix round that rewrites a bad test routinely deletes the coverage the bad test pretended to have — this is invisible in the diff and only mutation reasoning finds it. Ask for the mutation, not the assertion.
- **Write prescriptions as the property to hold, not the mechanism to add.** An orchestrator's dictated fix inherits none of the builder's context and all of the orchestrator's confidence. Measured: adjudicating a fail-open, the orchestrator specified "unless paired with `--fail-if-no-match`" — and the builder's blind self-review found `--fail-if-no-match=false` satisfies that pairing and restores the identical fail-open, discovered independently by both foreign lineages within minutes. The rule required a flag's *presence* where it needed its *value*. Say what must be true, name the defect it must survive, and instruct the round to attack the prescription before implementing it.
- **Every fix round must also prune.** A review loop that only adds constraints converges on a compliant artifact nobody wants. Measured at round eleven: a critic finally judged the *product* and found its most valuable screen space spent on arithmetic disclaimers about its own counts — a summary, a reconciliation, and a caveat, three lines explaining why the numbers do not add, above the numbers — with the diagnosis **"every correction added a clause, nothing ever removed one."** Each clause had been demanded by a round that was individually right. So: require each fix round to name **what its predecessors added that can now come out**, and which round added it; and tell critics explicitly that *over-disclosed, over-constrained, tedious* are reportable defects. Remove displayed prose, never a guarantee. A number that needs a disclaimer to be read correctly is the wrong number to show.
- **Ask every gauntlet for a product verdict, not only a compliance verdict.** Rotate one critic per phase onto "drive this as a user with a job; is it good?" Ten rounds of rule-checking critics missed that the artifact had become an artifact of the rule-checking.
- **Enumerate affordances and drive each one deliberately; a count of clicks is not a count of paths.** **Measured, definitively: on one artifact, enumerating 227 controls and driving 222 produced 1009 invariant violations in 5 classes, while 900 randomised clicks on the same build produced 0.** And the endgame of that same lane: a driver that **brings a control into existence** before clicking it (switch context, force the card open, open the panel) reached in two writes what had needed five, stabilised a denominator that oscillated by taking the **union over every state reached**, and reported its search shape honestly — complete breadth at depths 1–2, depths 3–5 sampled with an explicit budget, **476 states reached and 354 never expanded.** A sampled search states its depth, its branching budget, and its unexpanded count; "no violations found" over a sampled frontier is a claim about the sample. The payoff: it found a real defect at depth 4 that nothing shallower could reach, *and* found that the previous round's headline mutation could not flip a predicate — live, 308 times at depth 2, invisible to every instrument that existed before it. Random exploration does not cover sequences. **And enumeration has a depth**: the next review of that same artifact found two live violations at **depth 5**, on a control that does not *exist* until two prior writes have happened — invisible to per-control enumeration and to an independent depth-3 sequence sweep alike. So report three numbers, not one — controls enumerated, controls driven, and states reached at depth N with N stated — and check the denominator itself for holes: in that case the driver tagged only click-family events, leaving three keyboard write paths outside it entirely.
- **A claim about what a mechanism covers must be generated by the mechanism, not authored beside it.** Three consecutive rounds of one artifact shipped a real mechanism with its reach described from memory, and all three descriptions were false — a doctrine claiming a derived list while shipping a hand-written one, a comment citing an example the new walk could not see, and an enumerator documented with examples its own guard structurally excludes. Print the actual set, commit the output, have the prose cite that file. Any hand-written "for example, this now catches X" is a claim awaiting falsification.
- **Audit a prune for cost the way you audit a fix for coverage.** A prune reporting no cost has not been audited; a prune reporting one cost has not necessarily found them all. Measured: a round correctly declared one loss and had two, because it deleted a reconciliation clause while also changing one of the two predicates being reconciled — leaving two counts of the same thirteen records disagreeing on screen. And when you *move* an explanation rather than delete it, check that the condition you moved it behind is the condition it was about. Require the enumeration in the receipt (how many controls exist, how many were driven, which were not and why), then randomise on top.
- **When correcting an overclaim, the replacement is the highest-risk sentence in the commit.** It is written in the glow of having just done the work and is the sentence reviewers trust most. Measured: a round faulted for asserting a derivation it had not built then built the derivation — and wrote a new comment citing, as proof of coverage, an example the mechanism provably cannot see. Require the replacement to name the mechanism that makes it true **and** one example the mechanism does not cover.
- **State the defect precisely and the remedy tentatively.** A brief that specifies the fix turns the builder into an implementer of your first idea. Measured three rounds running: the orchestrator's proposed remedy was wrong each time and the better answer was already in the file — once in a comment the brief itself quoted. Mark every proposed remedy as a hypothesis, say what would falsify it, and ask explicitly to be told when it is wrong.
- **Read correctness artifacts as claims, not coverage.** Five times in two days the artifact establishing correctness sat beside the defect: a docblock one line above a fresh instance, a file answering one question twice in opposite directions, an authority-matrix cell marked *allowed* that was the bug, a correctly-scoped comment a reader over-generalised, and a **passing test asserting the defect was correct**. Tell critics to restate each `expect` as an English sentence and ask whether they would sign it. A passing test is evidence the code does what the test says, never that what the test says is right.
- **Budget a debugging pass for every new instrument, and verify its first finding by hand.** Five consecutive rounds had a fresh checker's inaugural finding turn out to be about the checker — a parser run over the wrong file type, a hit test fooled by `pointer-events:none`, a repro printing evidence contradicting its own headline, a checker crashing on a renamed property, and 222 spurious violations caused by a *different* checker's short reach. When instrument A feeds instrument B, B's false positives are evidence about A.
- **Record a refutation as "not reachable by X", never as "not a defect" — and name X.** A measurement bounds the dimension it varied. A positional claim was refuted because scrolling could not falsify it; expanding a collapsed group falsified it three clicks from boot.
- **A ticket holding N instances of one class is a class.** A fix round takes all N or states why the rest differ. Raiding it for one instance leaves the ticket looking triaged while the class stays open — measured: the instance left behind blocked its lane two rounds later.
- **Commit WIP early; infrastructure failure is correlated across agents.** Three rounds died inside one minute to one API failure, carrying 48KB, 40KB and 32KB of uncommitted diff between them. When it happens: back the work up (`git diff HEAD` plus every untracked file, outside the worktree) *before* touching anything, then resume from transcript rather than re-dispatching — a resumed agent keeps the context that produced the work.
- **Fix rounds are builders too**: new branch off the failing branch (`fix/<name>-r2`), only confirmed findings, explicit out-of-scope list ("scheduled tickets — do not build"), instruction to skip-and-say-so if a finding doesn't hold in source. A fix round may start on the first critic's confirmed findings while the second critic is still running — fold the delta in after.
- **Pass → close**: orchestrator merges (owning merge-conflict resolution — e.g. keep main's verified artifact over a builder's placeholder), closes the ticket, indexes the map. The final assembly ticket's gauntlet is the destination test itself; that ticket closing = campaign over, goal condition met.

**Freeze the review method periodically, or you cannot tell convergence from critic improvement.** Measured on a long campaign: critic capability rose every few rounds (source-reading → prepared trees → real databases → live stacks) while prompts and reporting requirements also changed, so defect counts, severities and even "what held" mentions all carry the orchestrator's own changes. The only defensible trend came from the one comparison where method was constant across consecutive rounds on one artifact. **Hold the apparatus still for two rounds on a schedule** and accept a slightly weaker review to buy an interpretable number.

## Phase 6: RETRO (standing, not terminal)

Retrospection is structural from day one, not a post-mortem. Create `RETRO.md` at the repo root during CHART with three standing rules: (1) **every closed build ticket appends an entry** — rounds taken, what each gauntlet round caught, findings refuted with evidence, one process lesson; no entry, no close. (2) **Everything expirable names its expiry condition** — fog entries state what they hang on (graduation is mandatory when it clears), decisions carry "reopen if wrong", briefs carry provenance headers. A weekly **automated staleness sweep** (cron) checks idle tickets, unmerged branches, fog-with-cleared-blockers, missing retro entries, and drifted metrics — findings comment on the map; a missing sweep comment >10 days is itself the top finding. (3) **Stay youthful** — phase-boundary retros must prune at least one process rule (kill it or re-justify in writing), fund one cheap divergent pass at something that already "works", track reopens as a vitality metric (zero-over-a-long-stretch is a warning), and rotate one critic lens per phase so critics don't groove. Transferable lessons promote upward: repo lessons stay in RETRO.md, cross-project lessons go to auto-memory, doctrine changes edit this skill.

## Anti-patterns (each cost something once)

- Sparse build tickets whose real spec lives in the orchestrator's session ("nobody should re-derive context" — enrich at birth).
- Letting critics or builders close tickets that need adjudication (research tickets are the one exception — their resolution IS the deliverable).
- Piping critic output through `tail`/`head` and losing the verdict.
- Treating "critic found missing X" as a defect when X is a scheduled ticket — route it, don't panic-fix it.
- Building #N+1 on files a fix round is reshaping because the graph said it was unblocked.
- A goal loop that resolves HITL decisions on invented preference instead of recorded authority — autonomous ≠ unaccountable; every resolution names its basis and stays reopenable.
