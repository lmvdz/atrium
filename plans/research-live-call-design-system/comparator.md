## 2. TRIED-AND-DROPPED

- **Canopy tree nav** — branching-SVG sidebar as primary nav metaphor (early Variant 1c "THE CANOPY"). Dropped before Prototype/v2; replaced by a flat sectioned list (ROOMS/AGENTS/HUMANS).
- **Node-edge process-map view** — literal graph diagram of the fleet (early Variant 1e "wildcard"), with its own unbuilt "list view ⇄ map view" toggle. Never built into Prototype, v2, or any later version.
- **Servers rail section** — a dedicated `SERVERS` list (dagon/acme/lab) in early Variant 1b. Dropped from Prototype/v2 onward; folded into per-agent `host` metadata instead of a top-level rail section.
- **Rail collapse** — a working fold/unfold toggle (`toggleRail`) in v3. Dropped in v4 (`railOpen` hardcoded `false`, `toggleRail` becomes a no-op).
- **Ticker chrome** — full dark terminal aesthetic with speech-as-ticker-bar (early Variant 1b "terminal dense"). Dropped; call+chat instead merged as parallel panes.
- **Giant-caption voice-first layout** — bottom-third-of-screen live caption with glowing avatar as primary layout (early Variant 1d "voice-first console"). Dropped as *the* primary layout for both Atrium and (independently) for glance's DECK exploration (full-width bottom call deck, turn 1d) — both branches tried a caption-dominant layout and both abandoned it.
- **`◌` glyph** for "orchestrating" — used only in early Variant 1e's legend. Replaced everywhere else by `◎` (ringed dot).
- **Receipt view full header** (name + meta + explicit close button in a bordered row) — present in v3. Removed in v4 in favor of an inline label-only chrome (no name, no close control).
- **Sora font** — imported via Google Fonts `<link>` in v3, v4, v5, and v6, but never referenced in any `font-family` declaration in any of the four files. A persistent, never-cleaned-up vestigial import across the entire late Atrium lineage.
- **DAYLIGHT / PLEX / DECK visual languages** — three of glance's four founding visual directions (turn 1 of Explorations: light-mode "spacious warm paper," blue-cast Discord-style "PLEX," warm-graphite "DECK"). All three lost to "WIRE" (all-mono terminal) by turn 2 and never recur in later turns.
- **"Crew" as a sub-identity/employment framing** — early brief's object model describes charm's sub-units as "crew sub-units" implying quasi-independent sub-agents. Glance's Object Model explicitly retires this: "what 'crew' used to mean... is now just 'the sessions of a plan.' No employment relationship, no sub-identities/sub-channels."
- **Spine-stack navigation** — glance turn 10 tests a spatial pushed-pane stack against a flat-breadcrumb-only trail. The brief records the A/B but not a winner; treat as unresolved rather than confirmed-dropped.
- **hexi as one collapsed focus target** — v3 treated hexi's two concurrent work-threads as a single agent-level focus. Superseded in v4 by independently addressable `hexi/auth` and `hexi/flaky` session nodes (an upgrade, not a pure drop, but the coarser model was abandoned).

## 3. Design tensions

1. **State-as-separate-panel vs. state-in-conversation.** Most explicit in mid's v3 Canvas A/B (1a: dedicated "current work" lens above the feed vs. 1b: pinned decision card embedded directly in the message stream). The separate-panel model (1a) shipped as the default in v3/v4/v5/v6; the fully-merged model (1b) did not survive as primary, though its call-pane guardrail copy did carry forward. Glance's resolution is a middle position: the pin sits structurally above the feed (not merged into it) but recurses inline for sub-units — neither pure separation nor pure merging.
2. **Density vs. approachability.** Early Variant 1a ("paper ledger" — airy, light, card-based) vs. 1b ("terminal dense" — dark, mono, ticker). The shipped Atrium answer sidesteps the choice via a runtime light/dark theme toggle rather than committing to one audience; glance instead commits fully to the dense/mono end (WIRE) and never ships its light-mode exploration (DAYLIGHT).
3. **Light-default vs. dark-default.** Atrium lineage ships light as the default theme with dark as a toggle, unchanged from Prototype through v6. Glance lineage ships dark-only (WIRE), having explicitly explored and dropped a light option (DAYLIGHT). The two branches never converged on this axis.
4. **Stated typographic principle vs. shipped typography.** Glance's own turn 4d states "machine chrome stays mono, human prose goes serif-less sans," but the Glance Room Prototype and Object Model that actually shipped are pure JetBrains Mono with no sans distinction at all. Atrium's shipped product is the one that actually implements the mono/sans split (Plex Mono for logs/timelines, Inter for chrome) — the principle and its implementation ended up on opposite branches.
5. **Terminal as convenience vs. terminal as break-glass exception.** Glance's Object Model insists "the terminal stays the break-glass exception" — steering should happen via the agent channel, with the loop routing it down; opening a terminal directly is an unmediated, higher-privilege escape hatch. Atrium's late lineage (v4 onward) adds a low-friction double-click-to-open-terminal interaction on nearly every session row, which sits in tension with treating the terminal as an exceptional, discouraged surface.
6. **Friction as a feature vs. friction as a cost.** Both branches agree that reversible gates should be fast (single click) while irreversible actions should be deliberately slow (hold-to-arm, 2s). This is a resolved tension rather than an open one, but it's the sharpest example in the corpus of intentionally asymmetric friction as a design tool.
7. **Flat, always-expanded tree vs. collapsible hierarchy.** v3's tree was flat and fully expanded; v4 restructured it into an explicit collapsible root/chevron hierarchy with sibling-dimming on focus. This trades a "see everything at once" simplicity for scalability as the fleet grows — the same navigation-depth tradeoff glance debates directly in turn 10 (spine-stack vs. flat trail) without a recorded resolution.

## 4. Non-obvious insights

1. **Independent convergence on the same epistemic/action vocabulary.** Despite being separate lineages — the late-Atrium brief explicitly notes "Glance" never appears in v5/v6, and the corpus gives no direct evidence of file lineage between the two — both branches arrive at the same glyph set (✓/~/·/◆/■/✗/●/◎/○), the same hold-to-arm mechanic, and the same voice-cannot-approve-destructive-actions boundary. Whether this reflects a shared origin later split, or deliberate reuse via the shared `support.js` runtime and token names (Process Tree.dc.html uses Atrium's CSS variables without defining them locally), the corpus doesn't resolve — but the convergence itself is the more interesting fact than its cause.
2. **Glance is where implementation-first patterns get promoted to written doctrine.** Lines that appear as UI copy in early Atrium ("needs-you first · everything else folds," Variant 1a) reappear as formal, numbered invariants in Glance's Object Model ("owed attention... never hides in a fold"). Glance's Object Model document reads less like a from-scratch spec and more like a retrospective theory pass over patterns the Atrium prototypes had already been shipping.
3. **The "crew" framing was quietly retired, but the underlying structure had already converged.** Early Atrium's object model describes an orchestrator's sub-units as "crew sub-units," implying quasi-independent sub-agent identities. Glance's Object Model explicitly abolishes this: "what 'crew' used to mean... is now just the sessions of a plan. No employment relationship, no sub-identities." Yet by late Atrium (v5/v6), the object model already matches Glance's simplified reading — Plans are named units "owned by" an orchestrator agent containing child Sessions — without the Atrium briefs ever framing this as a deliberate renaming. The two branches landed on the same three-noun structure from different directions.
4. **The visual-language split is a real fork, not a stylistic accident.** Atrium lineage is light-default with a dark toggle, warm-paper/pine-green; Glance lineage is dark-only mono "WIRE." Glance explicitly ran (and lost) a light-mode direction (DAYLIGHT) in its own bake-off. Given that a Glance file (Process Tree.dc.html) is authored against Atrium's own token variable names without redefining them, the two systems look like they were meant to merge — but nothing in the four briefs shows that merge having happened.
5. **Each Atrium version invested in a different layer of the trust problem.** Prototype→v2: trust/provenance (receipts fully built out, verified-vs-claimed marking, catch-up digest) — the first problem solved is "can I trust what I'm being told." v3→v4: hierarchy/addressability (sessions become independently addressable, the tree becomes collapsible, "the tree IS the nav") — the next problem is "can I find and scope the thing I need." v5→v6: explainability/correction (routing marked "inferred," reopen affordances, "why does this need a human" tooltips, live fleet-posture summary) — the last problem is "can I inspect and correct the system's judgment calls." This reads as a coherent, sequential arc, each phase assuming the prior phase's problem is solved.
6. **Refinement passes in this corpus are strictly additive.** The v3→v4 diff (~14 clusters) and v5→v6 diff (~44 lines) both show only additions/clarifications — no content removed — once the shell settled by Prototype/v2. The only phase with real deletions and dead ends is the earliest one (Variants' five divergent full-layout explorations). This suggests the fundamental shell and object model were locked in essentially at the start, and everything after is polish, not re-architecture.
7. **Wayfinding's mechanic survived a full rename with no functional change.** The pre-plan decision-map feature keeps the same underlying mechanic (open questions charted until a plan can be drafted) across mid and late Atrium, but its stage names shift wholesale — mid: destination→fog→frontier→decided→drafted; late: grill→fog→chart→clear→drafted. Notably, this feature has no counterpart anywhere in Glance's Object Model, consistent with Glance's own explicit self-exclusion (see #8) from anything terminal/session/plan-shaped — pre-planning is an orchestrator-agent concept, and Glance isn't one.
8. **Glance defines itself out of its own object model.** The Object Model states plainly: "Glance, the voice agent, is not a unit — it has no terminal and no sessions; it acts through the same channels you do." Glance is a first-class conversational participant (it takes turns in call transcripts) but is structurally exempt from the agent→plan→session hierarchy it so carefully specifies for every other actor. No equivalent asymmetry is discussed for Atrium's own assistant persona in the Atrium briefs.
9. **The newest ideas are also the least generalized.** Answer-binding and reopen-affordances appear only in v6, and per the late brief's own account, the reopen mechanic is wired to exactly one example gate rather than every gate type — i.e., the frontier of active design work in this corpus is legible from which features are still single-instance rather than systematized.
