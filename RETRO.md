# Retrospective log

Standing record of what this project's process gets wrong and right, kept so future decisions are made against evidence instead of memory. Rules:

- **Every closed build ticket appends an entry**: rounds it took, what each gauntlet round caught, findings refuted (with evidence), and the one process lesson worth keeping. The closing session writes it — no entry, no close.
- **Phase boundaries get a full retrospective** (below the running entries): metrics across tickets, doctrine changes, and what gets promoted to the `/campaign` skill or auto-memory (repo lessons stay here; transferable lessons go up).
- Product-level learning is separate and built-in: correction-rate telemetry per accepted object type (decisions #5/#17) is the product retrospecting on its own interpretations. This file is about *process*.

## Campaign to date — day-one retrospective (2026-08-01)

**Shape of the campaign so far**: 1 research pre-map (design corpus, 6 prototype versions mined) → map #1 charted with 17 decision tickets → 15 decisions + 3 research tickets resolved in ~one day → 9 build tickets graduated → 3 gauntlets run, all FAIL on round 1, all producing fix rounds that made the work *more architectural*, not more patched.

**What the gauntlet rounds actually caught** (evidence for the method):
- Scaffold r1 (grok + codex, blind): reducer accepted pre-blessed proposals; acceptance ignored proposal lifecycle; both lineages independently converged on the missing durable event ledger — convergence across uncorrelated critics proved to be the strongest signal available.
- Scaffold r2 delta (grok): the r1 fix's *contract claim* outran its guarantee — watermark-on-refusal still allowed live≡replay divergence. Root-cause fix (r3): rejection is a command-layer result, never state. Lesson: **a fix round's own claims need the same adversarial treatment as the original**.
- Prototype r1 (opus rendered + codex source): the answer-binding path hardcoded the answer — recording the *opposite* of what the user typed while labeled "nothing is inferred". Caught in 3 clicks by a critic who actually drove the page. Lesson: **rendered artifacts need a critic that renders them**; source review alone missed half the story.
- Ingest r1 (codex): pagination could silently write a valid-looking partial corpus. Lesson: **the fail-open class (valid-shaped incomplete output) recurs in every layer** — it has now appeared in the reducer, the compose stack, and the fetcher.

**Findings refuted, and why that matters**: 1 of ~40 adjudicated findings was wrong (MinIO healthcheck — the image ships `mc`; the suggested fix would itself have broken the chain), refuted by probing the live container, not by argument. Treating critic findings as hypotheses is not overhead; it caught the one that would have introduced a regression.

**Process corrections made mid-campaign** (each now encoded in `/campaign`):
- Build tickets were born sparse (spec lived in orchestrator prompts) — corrected to Tier-2 enrichment at creation after Lars flagged it. A ticket an agent can't pick up cold is a defect.
- Critic output piped through `tail -c` truncated a verdict; grok's default `--max-turns` once exited 0 with no verdict emitted. Both now handled (file capture; resume with higher turns; missing verdict ≠ pass).
- Demo corpus discovered mid-build to be structurally flat (GitHub issues carry no threading) — the corpus decision was amended on its closed ticket rather than silently changed. Amendments to closed decisions leave the same receipt trail as decisions.

**Metrics to watch as the campaign proceeds**: rounds-per-ticket (currently trending 2–3; if it hits 4+ the builders' first-pass bar is wrong, not the critics'), refuted-finding rate (currently ~2.5%; if it climbs, critics are pattern-matching instead of verifying), and time-from-FAIL-to-fix-dispatch (currently minutes; the gauntlet only works if rounds are cheap).

**Process note — a brand protects the shape, never the contents** (#39 UI r4, 2026-08-01, fourth address of one defect). The attribution guarantee was moved into a phantom-branded `Quotation` whose doc comment stated that spreading one value into another shape would not compile. TypeScript's object-spread type carries `unique symbol` keys through, so `{...genuineQuotation, actor: 'priya'}` keeps the brand, type-checks, and renders one person's name over another's sentence — and the same shape survives `JSON.parse` because the parser validates structure and never provenance. The render boundary passed because it re-derived the *body* and the forgery moved the *actor*. Lesson kept: **a nominal type proves where a value came from, not that its fields are consistent with each other — if two fields must agree (an actor and the message it came from), one of them has to be recomputed from the other at the point of use.** The defect's four addresses were the actor slot, the body slot, the factory, and the branded value itself; each round's guard governed what the previous round had moved.

**Process note — lexical overlap is not semantic support** (#21 core r3, 2026-08-01). The receipt rule bound a machine-minted claim to its evidence by requiring 60% of the assertion's content words to appear in the cited quote. `not` was on the stopword list, tokens were deduplicated, and the comparison was set containment — so a quote reading "Bob will **not** deploy production Friday" scored **100% support** for the commitment "Bob will deploy production Friday". Long, verbatim, correctly attributed, auto-accepted. Lesson kept: **a similarity measure used as an entailment check will accept the negation of the thing it validates** — polarity, quantifiers and modals are the content, not the noise, and word-overlap can never mean "this evidence supports this claim". Wider form: when a guard reduces meaning to a score, name what the score actually proves and refuse the cases it cannot judge, rather than letting a threshold stand in for judgement. This is the only defect in the campaign that would have written a false statement about a named person into the product's own record with every guard reporting success.

**Process note — doctrine written from one artifact must be swept across the others** (#10 r9 vs #39, 2026-08-01). `design/CONVENTIONS.md` gained two measured rules from the UI library's gauntlets — no alpha for inactive controls, and `--red3` rather than `--red2` at glyph sizes — each citing the exact contrast numbers that had been found there. The doctrine was correct, published, and never applied backwards to the artifact that shares its token set. Lesson kept: **when a finding becomes a rule, sweep every existing artifact for the rule before writing it down — publishing doctrine creates the illusion that the class is closed, and the older artifact is the one nobody re-reads.** Practical form: a doctrine commit should name which artifacts were checked against the new rule, or it is a plan rather than a fix.

**Process note — hardening one write path is worthless until you enumerate every path that reaches the same durable state** (#22 r6 gauntlet, 2026-08-01). Round 6 made the ledger's room CHECK genuinely unbreakable — a critic threw the r5 exploit, JSON nulls, numbers, arrays, empty strings, uppercase and braced UUIDs, duplicate keys, and a live `ALTER TYPE … ADD VALUE 'ninth_kind'` at it, all refused. Then it walked around it: **`NOTIFY` requires no privilege in Postgres.** A forged notification is cast rather than parsed by the bus, broadcast by the ws-server with no membership or room-ownership check, and the client's `applyEntry` **persists it to the durable journal and advances `lastSeq`** — so the real event at that sequence is permanently skipped. Executed: a client received a forged frame and diverged durably from the ledger while `core_events` held **zero rows**. Lesson kept: **a trust boundary is defined by the set of paths that reach the protected state, not by the one path you were reviewing** — enumerate every writer of every durable structure (including the client's own journal) before declaring a boundary closed. Corollary from the same review: two channels `JSON.parse(...) as T` where the ledger door parses with a schema; **a cast is an unchecked assertion wearing a type annotation.**

**Process note — a guarantee asserted in prose in two files and pinned by no test is not a guarantee** (#22 r6 gauntlet, 2026-08-01). Both `schema.ts` and the migration state that a `coalesce(…, false)` wrapper is what makes an unknown ninth event kind fail closed. Deleting the wrapper leaves **108/108 integration tests green** and the 58-mutant ledger unmoved — and the property is behaviourally real, since with it gone a ninth kind lands cross-room. A second mutation of the round's own stated design (`IS NOT DISTINCT FROM` → `=`) is likewise undetectable, and its written justification is no longer true of the shipped shape. Lesson kept: **every sentence in a comment claiming a safety property is a test that has not been written yet** — mutate each stated design decision and require something to go red, or delete the sentence. Note the shape: the ledger was sound (it runs a full green baseline per suite before mutating and excludes its own guard from scoring) and still could not see these, because **a mutation ledger only covers the mutations someone thought to list.**

**Process note — a platform's compile-time behaviour can be the bypass** (#22 r6 gauntlet, 2026-08-01). A call-stack guard checks `position('function atrium_append_core_event(' in v_context)`. The bypass is not merely "substring": PL/pgSQL builds the signature via `format_procedure` **at compile time**, which omits the schema qualifier when that schema is on `search_path` at that moment, and the compiled function is then cached for the session. Executed — create `evil2.atrium_append_core_event`, set the path before first compile, and a row lands in room B for a subject minted in room A, which is exactly the misroute the round's subject resolution exists to close. Only table CHECKs survive it. Meanwhile the migration asserts the guard runs "in the only function that can put a row in this table", and the round's whole room-less-kind guarantee rests on that sentence. Lesson kept: **when a guard depends on a platform behaviour, verify the behaviour under the conditions an attacker controls — including compilation order, caching, and search path — not under the conditions your tests happen to create.**

**Process note — the commit that names a defect class is the most likely place to commit it** (#40 r6, 2026-08-01). The general form of the resolution is the campaign's synthesis: stop proving the check *exists* and prove it *fires* — every registry row now carries a `violate` fixture the check must go red on, so a check gutted to `return []` fails regardless of how good its graph looks.

**Process note — a correct normalization that nothing consults is worse than none, because its comment becomes a guarantee about a different function** (#21 r5 gauntlet, 2026-08-01). `normalizeForReceipt` genuinely passes code spans through byte for byte, and its comment says why: *"two spaces in a password are a different password."* True — and the acceptance path never compares normalized strings. It compares `orderedTokens`, which discards **all whitespace and all standalone ASCII apostrophes**, and that comparison is the only one made between a quote and the statement minted from it. So `` Run `rm -rf / tmp/cache` `` certifies as `` Run `rm -rf /tmp/cache` `` — a different, destructive command produced by deleting a space — and `We will deploy production Friday, promise.` certifies as `We will 'deploy' production 'Friday', promise.` Lesson kept: **this is the campaign's synthesis in its purest form — the machinery was correct, and nothing used it.** When a value is carefully derived, ask which comparison actually runs; a docblock describing the careful function will be read as covering the path that ignores it. Related and equally sharp: backticks and double quotes are correctly refused as mention-markers so that a *displayed* sentence is not accepted as an *asserted* one — but the plain ASCII apostrophe is invisible to the tokenizer, so `'We will deploy production Friday.'` is accepted as an assertion, and the typographic pair survives only because `’` folds to `'` and vanishes while `‘` does not. **A guard that fails closed by luck rather than by rule is not a guard**, and the mention/use distinction has to be enforced by the same comparison that certifies, not by a sibling one.

**Process note — a rationale comment can be false about the language, not just about the code** (#21 r5 gauntlet, 2026-08-01). A docblock justifying a character-deletion class stated that "Tab, newline, vertical tab, form feed, carriage return **and NEL** are `\s`". JavaScript's `\s` does **not** include U+0085 NEL, nor U+007F, nor U+0080–U+009F. All of them are therefore deleted, fusing the words either side — `deploy\u0085production` becomes `deployproduction` and certifies clean — which is exactly the failure the comment was written to describe having fixed. The mutation guarding it repeated the same false claim in its own justification and exercised only `\t`, the one control character that *is* in `\s`. Lesson kept: **a comment asserting a language or platform property is a factual claim and must be enumerated, not reasoned about** — brute-force the codepoint range, print the set, commit the output. Four more comments in the same package were found false as written, including one still quoting an argument the round had explicitly deleted and one contradicted by another comment seventeen lines below it.

**THE SYNTHESIS — "a query was run" is not "the sentence came from the query"; provenance is checked by construction, use is checked by mutation** (#10 r11, 2026-08-01). Round 11 wrote the missing history-quantifier rule, made its second half structural (a query exists only on a view; a view exists only because `reads()` took one, so quantifying over an unread field becomes unwritable), and then found the eighth door **in its own fix**: minting a sentence from a query proves nothing about whether the sentence *used* the answer. The check is mutation — `say()` re-runs its own phrase with each answer flipped, and a sentence that does not move was decoration. **It fired 8 times against round 11's own code on the first run**, and the forgery suite then showed the mutation was owed to the read points too, catching two more.

This is the general form of nearly every defect in this campaign, and it belongs at the top of any future round's checklist:

- a CI gate whose assertion *ran* but whose result nothing consumed
- a flag required to be *present* whose value was never read (`--fail-if-no-match=false`, `VITEST_RUN_START=0`)
- a receipt line handed four record views that used **none** of them, rendering a hardcoded negation
- narration minted from correct values that printed a seeded literal
- a mutation ledger crediting catchers it never ran unmutated
- an audit reporting "0 failed" over a selector matching nothing

**Structure proves where a value came from. Only mutation proves it was used.** Ask of every guard, narration, gate and receipt: *if I flip the input, does the output move?* If not, the machinery is ornament regardless of how correctly it was assembled.

**Process note — a mutation ledger with no baseline run manufactures passes** (#39 r5 gauntlet, 2026-08-01). `pnpm test` exits 1 on a clean clone of the round that reported "101/101 mutations": a render throw escapes to React 19's global handler after the test's own `catch` swallows it, so `vitest` counts an unhandled error while the test itself passes. `test/mutations.mjs` decides "caught" purely from `execFileSync` throwing and **never runs the command unmutated**, so the two ledger entries naming that file are credited regardless of what the mutation does. **Process note — the round-level diagnosis: every lesson applied to one site and one neighbour** (#39 r5 gauntlet, 2026-08-01). **Process note — a source-grep can match a strict subset of a construct's syntax, which is a third failure mode** (#39 r5 gauntlet, 2026-08-01). **Process note — a stated limit is not a disposition; documenting what you cannot prove is not the same as declining to assert it** (#21 r4 gauntlet, 2026-08-01). Lesson kept: **a set of guards that share an execution substrate has a shared kill switch — enumerate what the substrate reads (environment, config files, preload hooks, module resolution) and treat that surface as part of the guard.** An allowlist over *how a command is written* does not cover *what the runtime does before main runs*.

**Process note — an allowlist entry can be its own bypass** (#40 r4, 2026-08-01). The same review found `node --disable-warning <script>`: an option the builder's own freshly-written allowlist had just admitted, which makes node consume the script path as the flag's value and exit 0 having run nothing, while the parser still reports the step present. Lesson kept: **every allowlist entry needs the same adversarial treatment as the denylist it replaced — admitting an option is a claim about all of its argument forms.** The admission criteria that came out of this are worth copying: for the launcher *and* each listed option, establish that it execs the command, runs it exactly once unconditionally, and waits and exits with its status; quote two measurements (`<launcher> false` non-zero, `<launcher> sleep 2` ≈ 2s); ship an accepted fixture proving the entry is reachable rather than decorative, and a rejected fixture for the nearest option that breaks one property. Governing rule: **no value of any listed option may produce exit 0 without the command having run to completion.**

**Process note — a self-adversarial pass can pay off without producing a verdict** (#40 r4, 2026-08-01). Three review attempts yielded no verdict at all: codex's long run was killed by its own content filter (the subject matter is shell-bypass technique), its short run hit a read-only sandbox, and grok exited cleanly with no findings section on three passes including `--max-turns 60`. All three of the round's real findings came from *leads in transcripts that never became reports*, reproduced by hand afterwards. Lesson kept: **a review's value is in what it surfaces, not in whether it renders a verdict — read the transcript of a failed run before discarding it, and never let "no verdict" mean "nothing found."** Corollary: some artifacts cannot be reviewed by some lineages at all; when a subject repeatedly trips a model's own filters, route it to a different reviewer rather than re-running.

**Process note — denylisting ways to not-run is unbounded; allowlist what may run** (#28 and #40, six rounds, 2026-08-01). The question "does this step actually run the assertion?" produced fifteen distinct bypasses across two tickets: `false &&`, `; true`, `echo exec`, a decoy `echo git fetch`, `node --check`, `xargs -r`, `sudo -b`, a `PATH` rebind, a one-shot env assignment, `sh -c`, `docker-compose`, and finally `setsid -f`. Each round folded the newest spelling into a denylist and the next spelling existed. Lesson kept: **when a guard enumerates ways to evade, it is unbounded by construction — invert it into an allowlist of forms that provably do the thing, and justify each entry.** The general shape: prefer "only these launchers, each of which is known to wait for exit status" over "not these fourteen ways to avoid waiting."

**Process note — the builder's own blind cross-lineage review found more than the gauntlet would have** (#40 r3, 2026-08-01). Before submitting, the builder ran an independent adversarial review of their own fix. It broke three of their four claims, and all fourteen findings reproduced against the engine exactly as committed: `node --check <script>` (syntax-checks rather than runs), `xargs -r node`, `sudo -b` (backgrounds it), a `PATH` assignment through a step `env:` block that the `no-command-shadowing` rule **had claimed to ban for two rounds**, a one-shot variable assignment recreating the precise preflight/boot divergence the round was closing, `docker-compose` and `sh -c` invisible to the compose rule, and a ledger that executed unwrapped argv so `timeout 30 node x` would have run as `node x`. Lesson kept: **a builder who has just written a guard is the best-placed person to attack it and the worst-placed to trust it — commission the adversarial pass as part of the build, not only after it.** Promoted into `/campaign`: for any round whose deliverable is itself a verification mechanism, the builder runs a blind foreign-lineage review of their own output before reporting, and lists what it broke.

**Process note — a crashed mutation run leaves the tree mutated and green** (#22 realtime r5, 2026-08-01). An interrupted ledger run left a substitution in `ws-server.ts`; `pnpm test` was green afterwards and `git status` could not distinguish the leftover from a fix branch's real work. Only a drift check inside the ledger noticed. The fix records the in-flight mutation and the file's original bytes, recovers a leftover file automatically, and refuses to start on a leftover SQL record. Lesson kept: **a tool that edits the tree must be crash-safe about it — record what it changed before changing it, and refuse to run on evidence of an interrupted predecessor.** A verification instrument that can silently corrupt the thing it verifies is worse than no instrument.

**Process note — a validation over a union must discriminate on the union's tag** (#22 realtime r5, 2026-08-01). A constraint meant to prove that an event's column-level room matches the room in its payload was written as a `coalesce` over every nested key a payload might carry. Coalesce is order-of-keys, not order-of-kind — and the storage layer accepts extra keys that the schema strips only *after* the row exists. So a caller supplies the real room in the key its kind actually uses, smuggles the desired room into a key belonging to a different kind, and the check reads the smuggled one. Lesson kept: **when validating a tagged union, read the tag first and require exactly the shape it names — a check that accepts "whichever of these keys is present" accepts the one an attacker chose to add.** Corollary for tests: exercising honest shapes proves nothing about a check whose defect is which shape it looks at.

**Process note — deriving beats validating, and removing beats deriving** (#22 realtime r5, 2026-08-01). Round 4 stored the receipt window in an immutable column and validated its shape; round 5 removed the parameter entirely and derived the value inside the boundary, with the append returning what it stored so the caller's fold can be compared against it and the transaction aborted on disagreement. The exploit test then attacked both positionally and *by name*, on the principle that "the argument moved to the end" is not a fix. Lesson kept: **when a caller-supplied value must be trusted, the strongest fix is to delete the argument — validation invites a bypass, derivation invites a divergence, and only absence invites neither.** The same audit found a second instance the round had not been asked about: a room id that no one compared to the room the payload declared.

**Process note — a wrong instrument invents defects, not just misses them** (#39 UI r4, 2026-08-01). Four instrument failures in one round: `getComputedStyle` read mid-transition reported an unfixed stylesheet as fixed; a `@ts-expect-error` stayed satisfied after the brand was deleted, because inferred widening made the forgery fail for an incidental reason; a regex over a CSS guard broke on a nested paren, matched nothing, and passed. The fourth is the new one — a `textContent` sweep reported eleven "welded" accessible names that a screen reader never hears, and fixing them would have redesigned working code. The corrected sweep (Playwright's aria snapshot) found three genuine ones instead. Lesson kept: **every previous instrument lesson was about a tool that could not see a defect; a tool can equally invent one, and acting on a false positive damages working code.** Before fixing what a sweep reports, confirm the sweep is reading what the user's actual consumer reads — the accessibility tree, the composited pixel, the settled style — not a convenient proxy for it.

**Process note — the instrument had the defect it hunts** (#26 auth r9, 2026-08-01). A mutation named `unguard-logger` silently stopped matching when the code it targeted moved files, and a `> /dev/null` inside a shell loop turned its throw into a green suite with a ledger row reading "0 caught" — a fail-open inside the tool built to find fail-opens. A second row simply carried the number from the row above it, in a table whose own header warns about that. Lesson kept: **a verification instrument needs the verification it provides — make it detect its own no-ops (does every mutation still match its target?) and prove every recorded number was produced by the run that claims it.**

**Process note — a guard must cover what is painted, not only what is stored** (#10 prototype r8, 2026-08-01, fourth appearance of one class). The round built a genuinely strong structural fix: one function mints every recorded change, marks it with an unforgeable token, and an invariant validates that the pair the record moved through actually exists. Every forgery attempt failed. And the defect persisted, because the renderer paints a *different* pair — a `was → now` string — that the invariant never inspects, so the checker was validating an invisible operand while a fabricated one was on screen. Lesson kept: **enumerate what the user can read, and check that; a guarantee that covers the stored representation and not the rendered one protects the database and lies to the reader.** The class has now moved outward four times — from the value, to the guard, to the guard's operands, to the operands the reader sees — and each round closed exactly one layer.

**Process note — a chokepoint is not a boundary** (#39 UI r2→r4, 2026-08-01). Three rounds enforced the same attribution guarantee at three different chokepoints, and each time a caller walked around it: the free string moved from the actor slot to the body slot; then a check went inside the only documented constructor, and a caller wrote the exported interface's literal directly and skipped it (`tsc` exit 0, a real person's name over words she did not write). Each fix was correct about the path it guarded. Lesson kept: **enforcing an invariant at a construction site protects only callers who use that site — close the type so no other value inhabits it, and re-derive at the render or write boundary, which is the one place a future call site cannot skip.** Ask of every guard: what is the *last* place this value passes before it becomes visible or durable, and is the check there?

**Process note — the audit-exemption class, three sites** (#39 UI r2/r3/r4, 2026-08-01). An audit skipping low-opacity elements hid two sub-3:1 controls; a doctrine paragraph (mine) authorized it; and a separate ring audit returned `null` for controls with no outline, dropping the app's only ring-less control — its primary input — from the measured set instead of failing it. Same shape, three files, one of them fixed in the same commit family that introduced the next. Lesson kept: **when a guard's rule is violated by exactly one element, suspect the guard before the element** — and grep the whole harness for `continue`, `return null`, and early exits whenever a rule appears to be universally satisfied.

**Process note — relocating a value into a trusted store does not make it trusted** (#21/#22, 2026-08-01, three appearances). The actor moved out of the event payload into a separate argument — and was still forgeable until the command layer *derived* it from the authenticated session. The receipt window moved out of the mutable `messages` table into an immutable ledger column — and is still forgeable, because the append boundary accepts it as a parameter and validates only its shape. Each move was correct and insufficient for the same reason. Lesson kept: **trust follows derivation, not location. When a value lands somewhere trusted, ask who computed it; if the answer is "the caller", the boundary must recompute or verify it, not merely store it.** Practical test for any new trusted column or argument: could a direct caller of the lowest-level write path supply a well-formed lie?

**Process note — the measuring instrument was wrong, and doctrine inherited it** (#39 UI r3, 2026-08-01). A contrast harness's block parser matched selector names inside `tokens.css`'s own provenance comment, so every "dark theme" assertion had been re-measuring light since the day it was written. Numbers from that harness reached two gauntlet receipts and then `design/CONVENTIONS.md`, where they were cited as universal floors. The practical rule survived (independent compositing measurements of real rendered rows agreed), but the justification was a light-theme argument stated as a general one. Lesson kept: **a measurement that becomes doctrine must record its instrument, and the instrument needs its own test — a self-check that fails loudly if two supposedly different configurations parse identically.**

**Process note — the orchestrator wrote the exemption it later criticized** (#39 UI r2→r3, 2026-08-01). I faulted an audit harness for skipping low-opacity elements; the harness was faithfully implementing an exemption *I had written into `CONVENTIONS.md` one paragraph above the rule* ("a disabled button at ~2.5:1 is an inactive-state exemption"). Two sub-3:1 elements survived two review rounds because of it, and one had never been named by any receipt. Lesson kept: **before faulting a guard for an exemption, check whether the doctrine authorized it — and when writing a rule, treat every exemption as an escape hatch someone will use correctly and unhelpfully.** The corollary now in CONVENTIONS: an audit may not exempt the case its rule covers.

**Process note — a house style can defeat source-grepping checks** (#39 UI r3, 2026-08-01). This repo's builders quote the defect they are forbidding directly above the fix, in a comment. A guard that greps source for the forbidden pattern therefore matched its own explanatory comment and passed on a mutated file. Every source-grepping check now strips comments first. Lesson kept: **a check that reads source must read what executes, not what is written — comments, strings and docs are not code, and this house's commenting style guarantees a collision.**

**Process note — "invoked" is not "runs"** (#40 r2 delta → #28, 2026-08-01). Six rounds of CI hardening asked whether a protected script was *invoked* in command position, and a parser answered correctly. `false && node scripts/ci/assert-page-serves.mjs; true` satisfies that question, skips the assertion, and exits green — while the mutation ledger, which recovers the script name by regex and executes it directly, certifies the assertion caught its mutation. Both halves of the verification stack agreed on something false. Lesson kept: **a guard on how a command is written must also ask whether it is reached; and a ledger must execute the validated command itself, not a name extracted from it — otherwise the ledger proves the script works, not that the pipeline runs it.**

**Process note — a timing test with generous slack measures "eventually", not the bound** (#26 auth r8, 2026-08-01). After I was corrected for accepting a bound without a measurement, the builder wrote one — a 40ms sweep interval with 250ms of slack, six intervals' worth, which passed against a sweep running four times less often. It was caught by `widen-sweep-window`, a mutation written to verify the fix, **which found the test instead**. Lesson kept: **a timing assertion's slack must be small next to the interval it measures, or it asserts liveness rather than the bound** — and the cheapest way to find out is to mutate the interval, not the code. Companion note from the same round: a ledger limitation recorded twice ("`--restore` is `git checkout --`") is a defect you have decided to keep paying for; the third encounter destroyed an uncommitted fix.

**Process note — a bug in the fix measured the vulnerability** (#40 r2, 2026-08-01). Building the image-identity binding, the first version ran `record-built-images` *with* the mutation overlay applied, so the `swapped-image` case recorded the doppelganger as "what this run built" and passed. That accident is a faithful model of the pre-fix state, and it answered the severity question directly: **without identity binding, a stack running an entirely different image passes every assertion in the job.** Found by running all 15 cases rather than by reading them. Lesson kept: **when a fix accidentally reproduces the defect it targets, that is the measurement — record what the accident proved rather than only fixing it.** Also recorded from the same round: the mutation ledger reads the working tree, so switching branches mid-run yields a false receipt; a ledger should assert a clean tree before trusting its own output.

**Process note — a checker can pass honestly on a fabricated input** (#10 prototype r7, 2026-08-01). The correction-chain invariant compares a change's `from` against its `to` and fires when they match. It passed on a chain entry asserting a change that never happened, because `from` was computed from the prior answer's *display text* — a system row reading "lars chose: X" — rather than from the statement the record actually held. The relationship the guard checked was true; its operands were wrong. The same class had already entered through two earlier paths, each time with a guard that was correct about what it compared and blind to where the values came from. Lesson kept: **a guard over a relationship is only as good as the provenance of its operands — validate where a value came from, not just how it relates to another value.** Practical form: when a check reads a field, ask which code path last wrote it and whether that path could have written a display string where a record value belongs.

**Process note — an accepted bound needs a measurement, not a paragraph** (#26 auth r6→r7, 2026-08-01, orchestrator error). I accepted a 15-second presence-after-removal window as a documented limitation and asked the builder to state it in code and the README. The delta review then showed the window was not a ceiling — a hung membership lookup leaves the sweep flag set and later intervals are skipped, so presence can persist indefinitely — and that the test written for it installed a 60-second interval and evicted via a command, never measuring the advertised window at all. Lesson kept: **accepting a limitation is a claim with a number in it, and numbers get measured. Require the test that measures the bound, and require it to fail when the bound is exceeded — otherwise "accepted" means "unexamined" and the documentation makes it look examined.**

**Process note — the guard written to excuse its own rule** (#39 UI r2, 2026-08-01). A contrast rule forbids unreadable de-emphasis; the audit harness enforcing it opened with `if (effectiveOpacity(el) < 0.999) continue;`, justified in a comment naming disabled chips as not-meant-to-be-read. So the one element violating the rule was the one element the guard skipped, and the suite stayed green. The critic's phrasing is the lesson: *the rule and the guard disagree, and the guard wins.* This is the same class as the prototype's sticky-footer whitelist, which had to be narrowed before the invariant could see its own defect. Lesson kept: **when a guard carries an exemption, the exemption is a claim about what the rule does not cover — check it against the rule's text, because an exemption written for convenience silently rewrites the rule.**

**Process note — a mutation ledger must run the real pipeline** (#28 r4 and #40 r1, 2026-08-01). Twice now a ledger has credited a mutation to a check that never ran: in CI, two mutations also tripped an earlier rule and would have gone red without the rule under test; in the deployment job, two cases were stopped by an earlier config assertion while the ledger invoked the later scripts directly and claimed those caught them. Both ledgers proved each check *can* fail in isolation — not that the pipeline catches each mutation by the named check. Lesson kept: **run every mutation through the real ordered pipeline and record which gate actually fired; when an earlier gate legitimately catches it first, say so.** A ledger that invokes checks directly is testing the checks, not the gate.

**Process note — deterministic code does not give deterministic replay** (#22 realtime r3, 2026-08-01). Receipt validation ran the same derivation function on the live-append and replay paths, and still diverged: its inputs came from a `messages` row whose `authorId` is `ON DELETE SET NULL`, so deleting a human author makes an acceptance that folded cleanly replay as a receipt failure and vanish from state. Grok's phrasing is the lesson — *same derivation code, different substrate*. Lesson kept: **an event-sourced system needs immutable inputs, not merely deterministic functions — anything a fold validates against must be snapshotted into the event at append time, or a later mutation of the source rewrites history.** Corollary: audit every FK with `SET NULL`/`CASCADE` that feeds a validation path.

**Process note — a mutation ledger against a stale build is a lie** (#26 auth r6, 2026-08-01). A `drop-join` mutation reported 7 passing suites; the Playwright tests import the package as its built `dist`, which had not been rebuilt, so the ledger measured the old artifact while claiming to measure the mutated source. Rebuilt, the same mutation failed 5 of 7. Lesson kept: **a mutation ledger must rebuild every artifact its suites consume, and say so in its header — otherwise "N mutations, N caught" measures whatever was on disk.** This is the second time the re-runnable-ledger rule has paid for itself in a day; the first (#21) turned 12 apparent catches into escapes.

**Process note — the orchestrator gave a builder a false premise** (#26 auth r6, 2026-08-01). The round-6 brief instructed the builder to register a workspace in `.github/ci-manifest.json`; that file and the whole `scripts/ci/` policy engine exist only on the CI branch, not on main or on theirs. They neither invented a gate nor silently skipped the item — they carried the manifest across, verified against the CI branch's own scripts, and reported the premise as false. Lesson kept: **a fix-round brief asserts facts about the tree, and those assertions are claims like any other — say which branch a referenced file lives on, and expect a builder to report back when a premise does not hold rather than papering over it.**

**Process note — an invariant enforced on half its surface** (#39 UI r1, 2026-08-01). Two blind critics from different lineages found the same architectural gap from opposite ends: the no-synthesized-speech enforcement covered the *words* and not the *attribution*. The excerpt type was branded, phantom-typed and constructor-guarded — while the primary message path stayed `actor + body: string[]`, so page-authored text rendered under a human's name in the shipped demo, and the quotation type deliberately discarded the actor it was minted from, leaving every name beside a quote an unchecked free string. Lesson kept: **when you enforce a rule with types, enumerate every path the rule's subject can travel and check the enforcement covers all of them — a guarantee on the secondary path reads as a guarantee on the primary one, to reviewers and to the next builder.** Corollary observed the same round: a claim of enforcement can be *narrower* than it sounds without being false, which is why receipts should record what a guarantee does NOT cover.

**Process note — a false safety claim is worse than no safety** (#39 UI r1, 2026-08-01). Destructive action buttons emitted `data-hold="2000"` with a tooltip promising a two-second press-and-hold, and fired on a single click — the attribute had no consumer anywhere in the codebase. The label and the tooltip both advertised friction that did not exist, on the one action class the design corpus singles out as requiring it. Lesson kept: **an affordance that describes a protection it does not implement is a defect of a higher order than the missing protection — ship it working or do not describe it.**

**Process note — four rounds fixing propagation when the fix was the read** (#26 auth r2→r6, 2026-08-01). Rounds 2 through 5 each closed a real revocation-propagation path: reconcile in the same transaction, evict the socket roster, order demotions before commits, serialize under an advisory lock. Every one was a genuine defect and every one left the class open, because room authorization read only the derived `memberships` table — so any cleanup failure still granted access. The structural fix (join `workspace_members` into the authorization query) makes authorization independent of cleanup succeeding at all. Independent confirmation arrived the same day from the Buzz research: their cross-community workflow leak and shared agent-nest bug are the same shape — authorization consulting a derived table rather than the source of truth. Lesson kept: **when successive rounds each fix a different path to the same failure, stop fixing paths and ask what the authorization actually reads — a guard that depends on cleanup having run is not a guard.**

**Process note — first-draft tests assert mechanisms instead of measuring them** (#26 auth r3/r4/r5, 2026-08-01). Three rounds running, a builder's own first-draft test was wrong about the mechanism it tested: one anchored on an invalid-JSON reply a closing socket cannot emit; one asserted `isSecureUrl('https:/host') === false` when WHATWG parsing of a special scheme tolerates the missing slash; one rebuilt the config block it was supposed to inspect and so survived its own mutation. Each was caught by the builder running it against the unfixed code rather than by reading it. Lesson kept: **a test's premise is a claim about a mechanism, and claims get measured — run every new test against the unfixed code before believing it, and read the value the system actually produces rather than the one the API docs imply.**

**Process note — the deployment nobody ran** (#26 auth r4 → #40, 2026-08-01). Three rounds of gauntlet receipts described a compose deployment that had never served a page: under `NODE_ENV=production` the app 500s on every request (a correctly-refused console mail transport; **corrected 2026-08-01 by measurement in #40** — the mechanism is not build-time inlining of `NODE_ENV` but `server.js` executing `process.env.NODE_ENV = 'production'` before any app code, so no runtime override of any spelling survives. The separate build-time inlining defect was real but applied to `NEXT_PUBLIC_WS_URL`, verified by finding a probe value baked into `.next/standalone/apps/web/server.js`), and no image had built at all since a new workspace package landed without being copied into the Dockerfiles. Every gate was green because every gate tested the parts. Lesson kept: **a deployment that nothing exercises end-to-end is a claim, not a deployment — put one assertion against the real shipped artifact in CI, and make it assert real behavior (a page, a flow) rather than a health endpoint.** Corollary for this campaign: the gauntlet reads code and runs suites; it cannot see that the product does not boot unless something boots it.

**Process note — two components that both "work" and never meet** (#22 realtime r2, 2026-08-01). The migration took advisory lock `1096041522`; the server took `0x41545232` = `1096045106`. Both took *a* lock, neither ever contended, and every single-process test stayed green — the mutual-exclusion guarantee was absent while all the evidence said it was present. Found by a test the builder wrote about the lock itself rather than about the behavior the lock protects. Lesson kept: **when two components must agree on a shared constant (lock key, queue name, topic, cache namespace), assert the agreement directly — testing each side's behavior in isolation cannot see the disagreement.**

**Process note — a fix that passes the rule you just wrote** (#10 prototype r5, 2026-08-01). Declaring the missing grid track fixed the reported defect but introduced a second: a `display:none` child is not a grid item, so hiding the optional region slid the composer onto a `1fr` track that resolved to 0 and pushed it off-screen. It passed both geometry invariants written moments earlier, and was found only by measuring boxes by hand afterward. Lesson kept: **an invariant written to catch a defect is calibrated to that defect — when your fix passes it, measure anyway, and treat the new invariant as untested until something else fails it.**

**Process note — hand-counted numbers always drift** (#28 CI, 2026-08-01). Three times in one ticket a number written in prose disagreed with the thing it counted: "15 rules" over 18, "five pairs" over nine, "four lookalikes" over five — the last one recurring within a day of the first being structurally fixed elsewhere. Each was corrected by *deriving* the number (declare the set, count it at runtime, print it from the self-test) rather than by fixing the text; the final round made the self-tests read the README's stated numbers back and compare. Lesson kept: **any count that appears in prose is a claim, and an underived claim drifts — derive it, or expect it to be wrong within the week.** Same round: a builder's first tightened matcher was itself satisfied by the decoy it was written to reject, caught only because they wrote the mutation before trusting the fix — **write the evasion first, then the guard.**

**Process note — a fix round can delete the coverage it appears to add** (#26 auth r3→r4, 2026-08-01). Rewriting a test that was theatre proved the new property (in-flight coalescing) but silently dropped the old property the theatre test had falsely claimed (sticky revocation): removing the `revoked` early-return would have passed. A critic found it by mutation reasoning, not by reading assertions. Three sibling tests had the same shape — one passes if the swept loop never runs, one is satisfied by an unrelated close handler, one is sequential where the risk is concurrent. **Standing rule adopted:** every test added or changed in a fix round must state the specific source mutation it now catches; a test whose mutation nobody can name is not yet a test.

**Process note — a receipt naming a syntax that does not exist** (#28 CI r4, 2026-08-01). The r3 delta critic faulted the source scanner for missing `test.each([...]).fails(...)`; the builder found that form is not a Vitest 4 API at all — it throws. But probing the real API surface, they wrote seven working evasions as actual test files, ran them, got 8 expected failures, and `vitest run` still exited 0: the line matcher missed five. Lessons: **a critic's named example can be wrong while its underlying finding is right — verify the mechanism, not the example**; and **when a witness is doubted, enumerate the real evasion set empirically (write the evading tests and run them) rather than reasoning about which forms exist.** The same round saw the rule-count mistake recur within a day of being structurally fixed elsewhere — a hand-counted number returns unless the count is derived.

**Process note — test theatre found by its own author** (#26 auth r3, 2026-08-01). A revocation test passed against both broken and fixed code: it sent its probe frames after the close handshake, and the `ws` client dropped them locally, so the assertion never reached the server. Rewritten as a ten-frame burst it failed against the *fixed* code too — `handleFrame` is fired-not-awaited, so every frame beat the cache check before the first lookup returned. Two lessons: **a test whose subject is a client-library side effect is testing the library, not the server**; and **a settled-verdict cache is worthless when the caller picks the burst size** — coalesce the in-flight lookup. The same round also refuted two of its own predecessor's claims in source (Next sets `x-forwarded-for` with `??=` rather than appending, so a hop count of 1 without a genuinely appending proxy is spoofable; a short forwarded chain clamped to the caller's own entry). Lesson kept: **builders auditing their own prior round find defects critics structurally cannot — schedule the self-audit, do not hope for it.**

**Process note — a test that could not fail** (#21 core engine, 2026-08-01). The acceptance rule-table test derived its probe confidences from the config it was testing, making it invariant under changes to those numbers: mutating claim θ_auto from 0.7 to 0.6 passed all 531 tests. Found by the builder's own mutation pass, fixed by pinning the table by value separately. Lesson kept: **a test that reads its expectations from the code under test proves only self-consistency — pin expected values literally, and mutation-test the numbers, not just the branches.** This is the assertion-side twin of the fail-open class the gauntlet keeps finding on the output side.

**Process note — orchestrator slips** (2026-08-01). Two in one merge: piping gate commands through `tail -1` masked a non-zero lint exit (pushed a red-lint main), and `git add -A` staged harness worktrees as gitlinks (pushed, then scrubbed). Both are the exact fail-open class the campaign hunts, committed by its orchestrator. Lessons kept: **never pipe a gate command's output — capture exit codes explicitly**; **never `git add -A` in a tree shared with harness state; add paths deliberately.**

**Process note — interpretation spike** (research, 2026-08-01). Measured on 6 live runs: model confidence carries no signal (0.937 on wrong vs 0.928 on right), so θ-band escalation routing was dead code as designed; #8 amended to deterministic pre-call text triggers. Lesson kept: **route on signals you compute, not signals the model self-reports; and test the cheap tier before building infrastructure around its assumed failure modes.**

## Anti-staleness doctrine

Nothing in this project is allowed to be true only at time of writing. Rules:

- **Everything expirable names its expiry condition.** Fog entries say what they hang on; when that condition clears, graduation is mandatory — a fog entry that outlives its condition is a defect, found by sweep. Decisions carry "reopen if wrong"; amendments land on the closed ticket, never as silent drift. Research briefs carry provenance headers (date + source versions) so staleness is *assessable*.
- **The weekly sweep** (scheduled, automated) checks: open tickets with no activity in 7 days; unmerged branches older than 7 days; fog entries whose named blocker has closed; closed build tickets missing their RETRO entry; RETRO metrics drifting past their stated thresholds; memory/map claims contradicted by repo state. Findings post as a comment on map #1 and, when real, append here. Anything needing a human lands in the attention queue.
- **Staleness of the sweep itself**: if a weekly sweep comment is missing from the map for >10 days, the automation is broken — that absence is itself the highest-priority finding.

## Staying youthful

Anti-staleness alone breeds calcification — a project that only audits itself becomes all immune system. Counter-rules, enforced at the same cadence:

- **Prune process, not just content.** Each phase-boundary retro must name at least one rule, gate, or metric that would NOT be adopted if starting fresh today — then kill it or re-justify it in writing. Process that survives only by inertia is stale process.
- **Budget for divergence.** The design corpus's own history is the evidence: every settled pattern came from its single wild breadth phase; six later versions refined and never re-architected. So at phase boundaries, spend one cheap Variants-style pass on a deliberately different approach to something that already "works" — most will lose, and the one that wins pays for all of them.
- **Reopening is health, not failure.** The reopen affordance exists in the product and the process for the same reason: a system that never revisits accepted state isn't stable, it's rigid. Track reopens in the retro as a vitality metric — zero reopens over a long stretch is a warning sign, not a win.
- **New eyes on old code.** Rotate at least one gauntlet critic lens per phase (a fresh failure-class prompt, a different lineage pairing) so the critics don't converge on the same grooves as the builders.

**Process note — gates that only break when the branches meet** (#40, 2026-08-01). Merging the CI branch into the auth branch to build the deployment job exposed two defects in gates that had passed on every branch individually: `assert-tables.mjs` derived expectations from `dist/schema.js` and reported the auth tables as schema drift, and the `e2e` job had no Postgres service and never ran its database setup. Neither branch could see its own hole, because each gate was only ever exercised against the tree that defined it. Lesson kept: **a verification gate is only tested by the integration it was written for — merge early enough that the gates meet before the code they guard does, or the first real merge is also the first real test of the guards.**

## Merge procedure for the pre-UI branch chains (2026-08-01)

`git merge-base` returns nothing between `main` and the older fix chains (`fix/realtime-*`, `fix/auth-*`, `fix/ci-*`); `build/ui-components`, branched from post-merge main, is unaffected. No force-push appears in the reflog and `main` is intact (14 commits, all merged content present) — the histories are disconnected while the **trees remain compatible**: each chain contains main's content as of its branch point plus its own work.

Verified divergence against `fix/realtime-r3`: it lacks only `plans/research-buzz/**` (added to main after it branched) and differs on `biome.json`, `RETRO.md`, `design/CONVENTIONS.md` — the three files main has moved forward.

Procedure, per branch, in merge-train order:
1. `git merge --allow-unrelated-histories -X theirs <branch>` — the branch wins, since it is main-at-branch-point plus its work.
2. Restore main's forward paths explicitly: `git checkout HEAD~1 -- biome.json RETRO.md design/CONVENTIONS.md plans/research-buzz` (adjust to whatever main has moved by then), then re-apply any doctrine the branch legitimately added to those files by hand.
3. Run the full gate with real exit codes (never pipe through `tail`) before committing the merge.

3. **Check for resurrected files.** `-X theirs`/`-X ours` does **not** suppress a delete or rename across unrelated histories: a file the branch renamed or deleted comes back from main's side, silently. Verified the hard way in #26 r7, where a renamed initial migration was resurrected — `0000_classy_shocker.sql` reappeared beside the branch's `0000_auth_and_workspaces.sql`, which would have meant two initial migrations and a broken database on any fresh boot. After every merge in this train, diff the merged tree against the branch tree and delete anything the branch had renamed or removed; check `packages/db/drizzle/` specifically.

Do not `--allow-unrelated-histories` without steps 2 and 3: the strategy option silently reverts main's doctrine files to their branch-point state, and silently resurrects whatever the branch renamed away.
